Section 2

SQL Syntax Differences

Most SQL is compatible but key syntax differs. These are the most common gotchas when migrating Oracle SQL to PostgreSQL.

Oracle vs PostgreSQL — Common SQL

-- Sequence / Auto-increment
Oracle:  CREATE SEQUENCE seq START WITH 1;
          INSERT ... VALUES (seq.NEXTVAL, ...);
PG:      id BIGSERIAL PRIMARY KEY;  -- auto
          OR id INT DEFAULT nextval('seq');

-- String concatenation
Oracle:  'Hello' || ' World'
PG:      'Hello' || ' World'  -- same!

-- Current date/time
Oracle:  SYSDATE,  SYSTIMESTAMP
PG:      CURRENT_DATE, NOW(), CURRENT_TIMESTAMP

-- NULL handling
Oracle:  NVL(col, 'default')
PG:      COALESCE(col, 'default')

-- ROWNUM (limit rows)
Oracle:  WHERE ROWNUM <= 10
PG:      LIMIT 10

-- Dual table
Oracle:  SELECT SYSDATE FROM DUAL
PG:      SELECT NOW()  -- no FROM needed

-- DECODE
Oracle:  DECODE(col, 'A', 1, 'B', 2, 0)
PG:      CASE WHEN col='A' THEN 1 WHEN col='B' THEN 2 ELSE 0 END

PL/SQL vs PL/pgSQL

-- Oracle PL/SQL block
DECLARE
  v_count NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_count
  FROM   employees;
  DBMS_OUTPUT.PUT_LINE(v_count);
END;
/

-- PostgreSQL PL/pgSQL equivalent
DO $$
DECLARE
  v_count INTEGER;
BEGIN
  SELECT COUNT(*) INTO v_count
  FROM   employees;
  RAISE NOTICE 'Count: %', v_count;
END;
$$ LANGUAGE plpgsql;
Section 3

PostgreSQL Administration for Oracle DBAs

Common DBA tasks in PostgreSQL — starting, monitoring, and managing the database.

Essential psql Commands

# Connect (equivalent to sqlplus / as sysdba)
psql -U postgres -d mydb

# psql meta-commands (like SQL*Plus commands)
\l          -- list databases (like v$database)
\c mydb     -- connect to database
\dt         -- list tables in current schema
\d tablename  -- describe a table (like DESC)
\du         -- list users/roles
\dn         -- list schemas
\timing     -- show query elapsed time
\x          -- expanded output (vertical)
\i file.sql -- run a SQL file (like @file.sql)
\q          -- quit

# Service management (Oracle Linux / systemd)
systemctl start postgresql-16
systemctl status postgresql-16

PostgreSQL Monitoring Views

-- Active sessions (like v$session)
SELECT pid, usename, application_name,
       state, query, wait_event_type,
       now() - query_start as duration
FROM   pg_stat_activity
WHERE  state = 'active'
ORDER BY duration DESC;

-- Table bloat / dead tuples (VACUUM needed)
SELECT schemaname, relname,
       n_live_tup, n_dead_tup,
       last_autovacuum, last_analyze
FROM   pg_stat_user_tables
ORDER BY n_dead_tup DESC;

-- Database sizes
SELECT datname, pg_size_pretty(pg_database_size(datname))
FROM   pg_database ORDER BY pg_database_size(datname) DESC;
Section 4

Oracle to PostgreSQL Migration

Common tools and strategies for migrating from Oracle to PostgreSQL — a growing requirement in cloud-first organizations.

ora2pg

Open-source Perl tool. Migrates schema (tables, indexes, constraints, views, packages) from Oracle to PostgreSQL format. Generates conversion report. Free.

Free & Popular

AWS SCT / DMS

AWS Schema Conversion Tool converts schema + code. AWS DMS (Database Migration Service) moves data continuously. Ideal for Oracle → Aurora PostgreSQL migrations.

Cloud Migration

GoldenGate / Debezium

For zero-downtime migrations — stream Oracle changes to PostgreSQL in real time using CDC (Change Data Capture). Cutover with minimal downtime.

Zero-Downtime
ora2pg — Schema Analysis & Export 
# Install ora2pg (requires DBI::Oracle Perl module)
cpan install DBD::Oracle
cpan install ora2pg

# Generate migration report (assess complexity)
ora2pg -c ora2pg.conf -t SHOW_REPORT --estimate_cost

# Export Oracle schema to PostgreSQL SQL file
ora2pg -c ora2pg.conf -t TABLE -o tables.sql
ora2pg -c ora2pg.conf -t SEQUENCE -o sequences.sql
ora2pg -c ora2pg.conf -t VIEW -o views.sql
ora2pg -c ora2pg.conf -t PROCEDURE -o procedures.sql

# Export data
ora2pg -c ora2pg.conf -t COPY -o data.sql

# Key ora2pg.conf settings:
# ORACLE_DSN = dbi:Oracle:host=dbserver;sid=ORCL;port=1521
# ORACLE_USER = myuser
# ORACLE_PWD = mypassword
# SCHEMA = MYSCHEMA
# PG_DSN = dbi:Pg:dbname=mydb;host=pgserver;port=5432
Section 5

PostgreSQL — Interview Q&A

Questions asked when Oracle DBAs are evaluated for PostgreSQL skills or migration projects.

Oracle uses an undo tablespace to store old row versions — when a transaction commits, the live row is updated in-place and undo space is reclaimed automatically. PostgreSQL uses MVCC with dead tuples — old versions of rows are stored in the same heap file as "dead tuples." VACUUM physically removes dead tuples and reclaims space. Without regular VACUUM (or autovacuum), tables grow indefinitely and performance degrades. PostgreSQL 14+ added improvements to make autovacuum more aggressive by default.

Both use MVCC (Multi-Version Concurrency Control) — readers never block writers and writers never block readers. The difference is WHERE old versions live: Oracle stores them in a separate undo tablespace; PostgreSQL keeps them inline in the same heap page as dead tuples. Oracle's model allows instant reclaim (undo overwrites after retention); PostgreSQL requires explicit VACUUM to clean dead tuples. The user-visible behavior (read consistency, isolation levels) is nearly identical.

  • Oracle PACKAGE concept doesn't exist in PG — split into schemas + functions
  • DBMS_* packages (DBMS_OUTPUT, DBMS_SCHEDULER, etc.) have no direct equivalents
  • PL/SQL-specific syntax: PRAGMA, TYPE ... IS TABLE, BULK COLLECT, FORALL
  • Oracle-specific functions: NVL, DECODE, TO_DATE formats differ
  • Implicit transactions — Oracle commits on DDL; PG DDL is transactional
  • CONNECT BY hierarchical queries → PostgreSQL uses WITH RECURSIVE
  • Oracle hints (/*+ INDEX, PARALLEL */) don't work in PG

pg_hba.conf (host-based authentication) is PostgreSQL's equivalent of Oracle's sqlnet.ora + listener security config. It controls WHO can connect, FROM WHERE, to WHICH database, and HOW (authentication method: md5, scram-sha-256, trust, peer, ldap, cert). Entries are matched top-to-bottom — the first matching rule applies. After editing, run pg_ctl reload or SELECT pg_reload_conf() — no restart needed.
