What is RMAN?

Recovery Manager Overview

RMAN is Oracle's native backup & recovery solution — automatically installed, tightly integrated with the database engine, and far superior to cold OS-level copies.

What RMAN Does

  • Block-Level Backup — only backs up used database blocks, not empty space
  • Incremental Backups — only changed blocks since last backup (Level 0/1)
  • Online Backup — backs up open databases (ARCHIVELOG mode required)
  • Corruption Detection — detects physical & logical block corruption during backup
  • Metadata Tracking — stores backup info in control file or recovery catalog
  • Parallelism — multiple channels for faster backup/restore

Understanding Backups

Backup Types & Strategies

RMAN offers multiple backup types — choose the right strategy based on your RTO/RPO requirements.

Backup Sets

Default Format
  • Proprietary RMAN format — only RMAN can read
  • Skips empty blocks — smaller backup size
  • Supports multiplexing (multiple files per set)
  • Supports compression and encryption
  • Restore required before use — slightly slower recovery
-- Create backup set (default)
BACKUP DATABASE;

-- Compressed backup set
BACKUP AS COMPRESSED BACKUPSET
  DATABASE PLUS ARCHIVELOG;

Image Copies

Bit-for-Bit Copy
  • Identical to OS-level file copy (cp, copy)
  • Recorded in RMAN repository for tracking
  • Usable directly — no restoration step needed
  • Includes empty blocks — larger size
  • Faster recovery with SWITCH DATABASE TO COPY
-- Create image copies
BACKUP AS COPY DATABASE;

-- Switch to image copy for fast recovery
SWITCH DATABASE TO COPY;
RECOVER DATABASE;
ALTER DATABASE OPEN;

Incremental Backup Strategy

Level 0 — Foundation Backup

Level 0 is functionally a full backup but labeled as the base of an incremental strategy. It copies every used block in the database. Required before any Level 1 incremental can be taken.

  • Copies ALL used blocks from data files
  • Creates the baseline for incremental chain
  • Typically scheduled weekly (Sunday)
  • Largest backup in the chain
Level 0 Backup
-- Full incremental base backup
BACKUP INCREMENTAL LEVEL 0
  DATABASE PLUS ARCHIVELOG
  FORMAT '/backup/lv0_%U_%T'
  TAG 'WEEKLY_FULL';

-- With compression
BACKUP AS COMPRESSED BACKUPSET
  INCREMENTAL LEVEL 0
  DATABASE;

Level 1 Differential (Default)

Backs up only blocks changed since the most recent Level 0 OR Level 1 backup. Each daily backup is small — only that day's changes.

Recovery Chain (Mon–Sun):
Sun: Level 0 (Full) ──────────────────┐
Mon: Level 1 Diff (since Sun L0) │
Tue: Level 1 Diff (since Mon L1) │
Wed: Level 1 Diff (since Tue L1) ──────┘
⚠ Recovery needs: L0 + all L1s in chain
Differential Incremental
-- Daily differential incremental
BACKUP INCREMENTAL LEVEL 1
  DATABASE PLUS ARCHIVELOG
  TAG 'DAILY_DIFF';

-- Backup is differential by default
-- equivalent to DIFFERENTIAL keyword:
BACKUP INCREMENTAL LEVEL 1
  DIFFERENTIAL
  DATABASE;

Level 1 Cumulative

Backs up ALL blocks changed since the last Level 0 backup (not since the last Level 1). Each backup grows daily — but recovery only needs Level 0 + the latest Level 1.

Recovery Chain (Mon–Sun):
Sun: Level 0 (Full) ──────────────────┐
Mon: Level 1 Cum (since Sun L0) │ larger
Tue: Level 1 Cum (since Sun L0) │ larger
Wed: Level 1 Cum (since Sun L0) ───────┘ largest
✓ Recovery needs: L0 + ONLY latest L1
Cumulative Incremental
-- Cumulative incremental
BACKUP INCREMENTAL LEVEL 1
  CUMULATIVE
  DATABASE PLUS ARCHIVELOG
  TAG 'DAILY_CUM';

-- Simpler recovery — only need L0 + last L1
-- Tradeoff: larger daily backup size

Production RMAN Script
-- Sunday: Weekly Level 0
BACKUP AS COMPRESSED BACKUPSET
  INCREMENTAL LEVEL 0
  DATABASE PLUS ARCHIVELOG
  FORMAT '/backup/%d_L0_%U_%T'
  TAG 'WEEKLY_FULL';

-- Mon-Sat: Daily Level 1
BACKUP AS COMPRESSED BACKUPSET
  INCREMENTAL LEVEL 1
  DATABASE PLUS ARCHIVELOG
  FORMAT '/backup/%d_L1_%U_%T'
  TAG 'DAILY_INCR';

-- Always delete obsolete after backup
DELETE NOPROMPT OBSOLETE;

Rolling Forward (Optimized Incremental Merge)

Advanced strategy: maintain an image copy on disk, and daily merge Level 1 incremental into it. The disk copy is always only 1 day old — enabling near-instant recovery via SWITCH DATABASE TO COPY.

Optimized Incremental Merge
-- Daily job: merge incremental into base copy
RUN {
  -- Step 1: Apply yesterday's incremental to copy
  RECOVER COPY OF DATABASE
    WITH TAG 'INCR_MERGE';

  -- Step 2: Take new Level 1 incremental
  BACKUP INCREMENTAL LEVEL 1
    FOR RECOVER OF COPY WITH TAG 'INCR_MERGE'
    DATABASE;
}

-- Fast recovery: database copy is <= 1 day old
SWITCH DATABASE TO COPY;   -- near-instant!
RECOVER DATABASE;
ALTER DATABASE OPEN;
RMAN Setup

Configuration & Commands

RMAN configuration persists across sessions and controls how backups behave — retention, compression, channels, and autobackup.

Retention Policy Types

Redundancy

Keep N full backups of each file. Oldest beyond N become obsolete.

CONFIGURE RETENTION POLICY TO REDUNDANCY 2;
Recovery Window

Guarantee recovery to any point within N days. RMAN retains all necessary backups.

CONFIGURE RETENTION POLICY TO RECOVERY WINDOW OF 7 DAYS;
Archive Log Deletion

Delete archive logs only after backed up N times to a device type.

CONFIGURE ARCHIVELOG DELETION POLICY TO BACKED UP 2 TIMES TO DEVICE TYPE DISK;
Retention Management
-- View current retention setting
RMAN> SHOW RETENTION POLICY;

-- Set redundancy (keep 2 full backups)
CONFIGURE RETENTION POLICY TO REDUNDANCY 2;

-- Set recovery window (7 day PITR)
CONFIGURE RETENTION POLICY TO
  RECOVERY WINDOW OF 7 DAYS;

-- Check what is obsolete
RMAN> REPORT OBSOLETE;

-- Delete obsolete backups
RMAN> DELETE NOPROMPT OBSOLETE;

-- Files needing backup
RMAN> REPORT NEED BACKUP;

Control File Autobackup

When enabled, RMAN automatically backs up the control file and SPFILE after every structural change or backup command. Always enable this — it's your lifeline when control files are lost.

Default Autobackup Format:
c-IIIIIIIIII-YYYYMMDD-QQ
  • IIIIIIIIII = DBID (10-digit)
  • YYYYMMDD = backup date
  • QQ = hexadecimal sequence 00-FF
Triggers autobackup when:
  • Any RMAN backup/copy completes
  • New tablespace or datafile added
  • Online redo log group added
  • RMAN catalog changes
Autobackup Configuration
-- Enable autobackup (CRITICAL!)
CONFIGURE CONTROLFILE AUTOBACKUP ON;

-- Custom format for disk
CONFIGURE CONTROLFILE AUTOBACKUP FORMAT
  FOR DEVICE TYPE DISK TO
  '/backup/cf_%F';

-- SPFILE recovery when instance is down
RMAN> SET DBID=2968723077;
RMAN> STARTUP FORCE NOMOUNT;
RMAN> RESTORE SPFILE FROM AUTOBACKUP;
RMAN> SHUTDOWN IMMEDIATE;
RMAN> STARTUP MOUNT;
RMAN> RESTORE CONTROLFILE FROM AUTOBACKUP;
RMAN> RECOVER DATABASE;
RMAN> ALTER DATABASE OPEN RESETLOGS;

Channels & Parallelism

A channel = one stream of data = one server session. More channels = more parallel streams = faster backups.

DISK Channel
Writes to filesystem — no media manager needed. Path specified in FORMAT parameter.
SBT Channel (Tape)
Writes to tape via media management library (MML). Requires Oracle Secure Backup or 3rd-party MML.
Automatic vs Manual
CONFIGURE sets persistent defaults. ALLOCATE in RUN block overrides for that session only.
Channel Configuration
-- Auto: 4 parallel disk channels
CONFIGURE DEVICE TYPE DISK
  PARALLELISM 4;
CONFIGURE CHANNEL 1 DEVICE TYPE DISK
  FORMAT '/disk1/backup_%U';
CONFIGURE CHANNEL 2 DEVICE TYPE DISK
  FORMAT '/disk2/backup_%U';

-- Manual: RUN block with custom channels
RUN {
  ALLOCATE CHANNEL ch1 TYPE DISK
    FORMAT '/bkp1/%U';
  ALLOCATE CHANNEL ch2 TYPE DISK
    FORMAT '/bkp2/%U';
  ALLOCATE CHANNEL ch3 TYPE DISK
    FORMAT '/bkp3/%U';
  BACKUP DATABASE PLUS ARCHIVELOG;
  RELEASE CHANNEL ch1;
  RELEASE CHANNEL ch2;
  RELEASE CHANNEL ch3;
}

Backup Encryption

Transparent (Default)
Uses Oracle keystore (TDE master key). No DBA intervention needed daily. Each backup piece gets unique key stored encrypted inside it.
Password-Based
No keystore required. Must provide password during backup AND restore. Useful for off-site/transportable backups.
Dual Mode
Encrypted with BOTH password + keystore. Restorable via either method. Best for hybrid on-site/off-site strategy.
Encryption Commands
-- Transparent encryption (persistent)
CONFIGURE ENCRYPTION FOR DATABASE ON;
CONFIGURE ENCRYPTION ALGORITHM TO
  'AES256';  -- default: AES128

-- Password encryption (session only)
SET ENCRYPTION ON
  IDENTIFIED BY 'MyP@ssw0rd' ONLY;
BACKUP DATABASE;
SET ENCRYPTION OFF;

-- Restore encrypted backup (pwd mode)
SET DECRYPTION IDENTIFIED BY
  'MyP@ssw0rd';
RESTORE DATABASE;
RECOVER DATABASE;

Real-World DBA Skills

Recovery Scenarios

Step-by-step recovery procedures for every failure scenario a production DBA will encounter.

Complete Database Restore & Recovery

Used when ALL datafiles are lost (disk failure, rm -rf accident). Requires ARCHIVELOG mode and recent backup.

1
Shut Abort (if still up)
Force-kill the instance
2
Startup MOUNT
Instance up, DB not open — control file exists
3
RESTORE DATABASE
Copies datafiles from backup to original locations
4
RECOVER DATABASE
Applies archive logs to bring DB to current SCN
5
ALTER DATABASE OPEN
Database is live again
Complete DB Restore
-- Scenario: all datafiles deleted
-- $ rm /u02/oradata/ORCL/*.dbf

SQLPLUS '/as sysdba'
SHUT ABORT;
STARTUP NOMOUNT;

RMAN TARGET /

RUN {
  ALTER DATABASE MOUNT;
  RESTORE DATABASE;
  RECOVER DATABASE;
  ALTER DATABASE OPEN;
}

-- Verify
SELECT name, open_mode FROM v$database;
SELECT COUNT(1) FROM labdba.employees;

Loss of System Datafile

SYSTEM tablespace is critical — database cannot open without it. Must be recovered while DB is in MOUNT state.

System Datafile Recovery
-- $ rm /u02/oradata/ORCL/system01.dbf
SHUT ABORT;
STARTUP MOUNT;

-- Check file status
SELECT file#, name, status FROM v$datafile;

RMAN TARGET /

RUN {
  RESTORE DATAFILE 1;      -- file# 1 = SYSTEM
  RECOVER DATAFILE 1;
  ALTER DATABASE OPEN;
}

-- Verify SYSTEM tablespace online
SELECT tablespace_name, status
FROM   dba_tablespaces
WHERE  tablespace_name = 'SYSTEM';

Non-System Datafile Recovery (Online)

Non-system datafiles can be recovered while the database remains OPEN. Take the datafile offline, restore, recover, bring online.

Online Datafile Recovery
-- $ rm /u02/oradata/ORCL/users01.dbf (file# 4)
-- Database is still OPEN (READ WRITE)

ALTER DATABASE DATAFILE 4 OFFLINE;

RMAN TARGET /

RUN {
  RESTORE DATAFILE 4;
  RECOVER DATAFILE 4;
  SQL 'ALTER DATABASE DATAFILE 4 ONLINE';
}

-- Verify
SELECT file#, ts#, status FROM v$datafile WHERE file#=4;
SELECT COUNT(1) FROM labdba.employees; -- data still accessible

-- Restore to different location
RUN {
  SET NEWNAME FOR DATAFILE 4
    TO '/new/path/users01.dbf';
  RESTORE DATAFILE 4;
  SWITCH DATAFILE 4;
  RECOVER DATAFILE 4;
  SQL 'ALTER DATABASE DATAFILE 4 ONLINE';
}

Tablespace Recovery

Recover an entire tablespace — can be done online (DB open) for non-SYSTEM tablespaces.

Tablespace Recovery
-- Option 1: Online recovery (DB stays open)
SQLPLUS '/as sysdba'
ALTER TABLESPACE users OFFLINE IMMEDIATE;

RMAN TARGET /
RESTORE TABLESPACE users;
RECOVER TABLESPACE users;

SQLPLUS '/as sysdba'
ALTER TABLESPACE users ONLINE;

-- Option 2: Mounted recovery (DB offline)
SHUT ABORT;
STARTUP MOUNT;

RMAN TARGET /
RUN {
  RESTORE TABLESPACE users;
  RECOVER TABLESPACE users;
  SQL 'ALTER DATABASE OPEN';
}

-- Verify
SELECT tablespace_name, status
FROM   dba_tablespaces
WHERE  tablespace_name = 'USERS';

Control File Recovery

Without control file, DB cannot mount. Use RMAN autobackup. After restore, always open with RESETLOGS.

Control File Recovery
-- $ rm /u02/oradata/ORCL/control0*.ctl
SHUT ABORT;

RMAN TARGET /

-- DBID required when no catalog
SET DBID=3580177852;

STARTUP NOMOUNT;

-- Restore control file from autobackup
RESTORE CONTROLFILE FROM AUTOBACKUP;

-- Or from specific piece
-- RESTORE CONTROLFILE FROM
--   '/backup/c-3580177852-20260511-00';

ALTER DATABASE MOUNT;

RECOVER DATABASE;

ALTER DATABASE OPEN RESETLOGS;

-- CRITICAL: register new incarnation
RESET DATABASE;   -- if using catalog
LIST INCARNATION; -- verify
-- Then take a fresh full backup immediately!

SPFILE Recovery

Without SPFILE, the instance cannot start. RMAN autobackup is the standard recovery path.

SPFILE Recovery
-- Case 1: FRA configured
RMAN TARGET /
SET DBID=2968723077;
STARTUP FORCE NOMOUNT;
RESTORE SPFILE FROM AUTOBACKUP;
SHUTDOWN IMMEDIATE;
STARTUP;

-- Case 2: Non-FRA autobackup location
RMAN TARGET /
SET DBID=2968723077;
STARTUP FORCE NOMOUNT;
RUN {
  CONFIGURE CONTROLFILE AUTOBACKUP FORMAT
    FOR DEVICE TYPE DISK TO '/backup/cf_%F';
  RESTORE SPFILE FROM AUTOBACKUP;
}

-- Case 3: Direct file reference
RESTORE SPFILE FROM
  '/backup/c-2968723077-20260510-00';

-- After SPFILE restore: generate pfile to edit paths
SQL> CREATE PFILE FROM SPFILE;
-- Edit pfile, then: CREATE SPFILE FROM PFILE;

Point-in-Time Recovery (PITR)

Recover to a specific time, SCN, or log sequence. Used when a logical error occurred (bad DML/DDL). Always opens with RESETLOGS — register new incarnation.

Point-in-Time Recovery
-- Recover to specific TIME
RMAN TARGET /

RUN {
  SET UNTIL TIME
    "TO_DATE('2026-05-10 12:00:00',
             'YYYY-MM-DD HH24:MI:SS')";
  RESTORE DATABASE;
  RECOVER DATABASE;
}
ALTER DATABASE OPEN RESETLOGS;

-- Recover to specific SCN
RUN {
  SET UNTIL SCN 136846506;
  RESTORE DATABASE;
  RECOVER DATABASE;
}
ALTER DATABASE OPEN RESETLOGS;

-- Recover to log sequence
RUN {
  SET UNTIL SEQUENCE 1202 THREAD 1;
  RESTORE DATABASE;
  RECOVER DATABASE;
}
ALTER DATABASE OPEN RESETLOGS;

-- Register new incarnation in catalog
RESET DATABASE;
LIST INCARNATION;

Restore from Specific TAG (Catalog Scenario)

Real-world PITR using RMAN catalog to restore from a specific backup date

Catalog-Based TAG Restore
-- Connect to target + catalog
rman catalog rman_user/password@catdb target sys/password@prod

-- Find the backup tag for the date you need
LIST BACKUP SUMMARY COMPLETED AFTER 'sysdate-2';

-- Restore controlfile from specific tag
RUN {
  ALLOCATE CHANNEL ch1 TYPE DISK;
  RESTORE CONTROLFILE FROM TAG 'TAG20090915T182528';
  RELEASE CHANNEL ch1;
}

ALTER DATABASE MOUNT;

-- Restore database from specific date tag
RUN {
  ALLOCATE CHANNEL ch1 TYPE DISK;
  ALLOCATE CHANNEL ch2 TYPE DISK;
  RESTORE DATABASE FROM TAG 'TAG20090915T182007';
  RELEASE CHANNEL ch1;
  RELEASE CHANNEL ch2;
}

-- Recover to specific time
RECOVER DATABASE UNTIL TIME '2009-09-16:12:00:00'
  USING BACKUP CONTROLFILE;

ALTER DATABASE OPEN RESETLOGS;

-- Add temp tablespace after RESETLOGS
ALTER TABLESPACE temp ADD TEMPFILE
  '/u02/oradata/ORCL/temp01.dbf' SIZE 200m;

-- Re-register incarnation in catalog
RESET DATABASE;
FRA

Fast Recovery Area

A dedicated disk location that Oracle manages automatically for all backup and recovery-related files — the cornerstone of a modern RMAN strategy.

What FRA Contains

Control Files (copies)
Auto-managed copies of control files
Online Redo Logs (copies)
Multiplexed redo log members
Archived Redo Logs
Auto-archived logs for recovery
Flashback Logs
Required for Flashback Database
RMAN Backups
Backup sets and image copies
FRA Configuration
-- Set FRA location and size
ALTER SYSTEM SET
  db_recovery_file_dest_size = 100G
  SCOPE=BOTH;

ALTER SYSTEM SET
  db_recovery_file_dest =
  '/u03/fast_recovery_area'
  SCOPE=BOTH;

-- Optional: Flashback (24 hours)
ALTER SYSTEM SET
  db_flashback_retention_target = 1440
  SCOPE=BOTH;

-- Enable flashback logging
ALTER DATABASE FLASHBACK ON;

-- Monitor FRA usage
SELECT space_limit/1024/1024/1024 total_gb,
       space_used/1024/1024/1024  used_gb,
       space_reclaimable/1024/1024/1024 reclaimable_gb
FROM   v$recovery_file_dest;
FRA Space Breakdown
SELECT file_type,
       ROUND(space_used/1024/1024,2) used_mb,
       ROUND(space_reclaimable/1024/1024,2) reclaim_mb,
       percent_space_used pct
FROM   v$recovery_area_usage
ORDER BY space_used DESC;

-- Backup FRA to remote disk (11g+)
RMAN TARGET /
BACKUP RECOVERY AREA TO DESTINATION
  '/mnt/remote/backups/FRA_BACKUP/';

FRA Sizing Formula

= DB Size × copies
Full database copy (largest component)
+ Archive Log Space
(n+1) days of archive generation rate
+ Flashback Logs
If flashback database is enabled

Rule of thumb: FRA = 3× database size. Oracle automatically reclaims space per retention policy when FRA nears capacity.

Power Features

Advanced RMAN Features

Block change tracking, block recovery, table recovery, and cross-platform migration — the features that separate senior DBAs.

Block Change Tracking (BCT)

Enterprise Edition

BCT maintains a file that tracks which blocks changed since the last RMAN Level 0 backup. Eliminates scanning the entire datafile for incremental backups — dramatically reduces backup time for large databases.

  • File size ≈ 1/30,000 of tracked data (10MB per 300GB)
  • 1TB database → ~40MB tracking file
  • Available since Oracle 10g Enterprise Edition
  • 90%+ reduction in incremental backup scan time
-- Enable BCT
ALTER DATABASE
  ENABLE BLOCK CHANGE TRACKING
  USING FILE '/u02/bct/bct.f';

-- Verify
SELECT status, filename,
       ROUND(bytes/1024/1024,1) size_mb
FROM   v$block_change_tracking;

Block-Level Recovery

Database Stays Open

From Oracle 9i onward, RMAN can recover individual corrupted blocks without taking the database offline. Targeted block recovery is vastly faster than a full datafile restore.

  • Database remains open during recovery
  • Only corrupted blocks restored from backup
  • Detect corruption: ORA-01578, V$DATABASE_BLOCK_CORRUPTION
  • Use DBVERIFY utility for full datafile scan
-- Identify corrupted blocks
SELECT * FROM v$database_block_corruption;

-- Verify with DBVERIFY (OS)
$ dbv file=users01.dbf BLOCKSIZE=8192

-- Recover specific block
BLOCKRECOVER DATAFILE 48
  BLOCK 142713;

-- Recover all from corruption list
BLOCKRECOVER CORRUPTION LIST;

12c RECOVER TABLE

Oracle 12c+

Restore a single table or partition from an RMAN backup without full database downtime. RMAN creates a temporary auxiliary instance, restores the relevant tablespace to a point-in-time, exports the table via Data Pump, then imports it back.

  • Use when FLASHBACK TABLE lacks sufficient undo
  • Use when FLASHBACK DATABASE would revert too much
  • No downtime for other tables
  • Works with CDB/PDB (target specific PDB)
-- Recover a table to 10 minutes ago
RECOVER TABLE sh.customers
UNTIL TIME 'sysdate-10/1440'
AUXILIARY DESTINATION
  '/u01/app/oracle/aux_dest'
DATAPUMP DESTINATION
  '/u01/app/oracle/dp_dest';

-- Process: aux instance → restore →
-- recover → expdp → impdp → cleanup

Flashback Database

Near-Instant Rewind

Flashback Database is NOT a restore from backup — it uses flashback logs to rewind the database to a previous point in seconds. Much faster than PITR but requires FRA and flashback logging enabled.

  • Rewind entire database in seconds/minutes
  • Requires flashback logs in FRA
  • Limited by DB_FLASHBACK_RETENTION_TARGET
  • Open READ ONLY first to verify before RESETLOGS
RMAN> SHUTDOWN IMMEDIATE;
RMAN> STARTUP MOUNT;

-- Flashback to SCN
FLASHBACK DATABASE TO SCN 861150;

-- Verify in READ ONLY
ALTER DATABASE OPEN READ ONLY;
-- run queries...
SHUTDOWN IMMEDIATE;
STARTUP MOUNT;

-- Confirm if correct
ALTER DATABASE OPEN RESETLOGS;

SWITCH DATABASE TO COPY — Near-Zero RTO

The ultimate fast recovery: maintain an always-current image copy on disk using incremental merge. When disaster strikes, switch the database to point at the disk copy — recovery completes in seconds, no tape restore needed.

Daily Merge Script (cron job):

-- Run daily — keeps disk copy current
RUN {
  -- Apply yesterday's L1 to disk copy
  RECOVER COPY OF DATABASE
    WITH TAG 'DISK_COPY';

  -- Take new L1 incremental
  BACKUP INCREMENTAL LEVEL 1
    FOR RECOVER OF COPY
    WITH TAG 'DISK_COPY'
    DATABASE;
}

When Disaster Strikes:

-- $ rm /u02/oradata/ORCL/*.dbf
STARTUP MOUNT;

RMAN TARGET /

-- Point control file at disk copy
SWITCH DATABASE TO COPY;

-- Apply archive logs (minimal)
RECOVER DATABASE;

-- Open — SECONDS of downtime!
ALTER DATABASE OPEN;

DELETE NOPROMPT EXPIRED ARCHIVELOG ALL;

-- Validate backup integrity
RESTORE DATABASE VALIDATE;
RESTORE DATABASE VALIDATE CHECK LOGICAL;
VALIDATE BACKUPSET 42;
RESTORE ARCHIVELOG FROM TIME
  'sysdate-1' VALIDATE;

FRA & Archive Log Monitoring

-- FRA space usage
SELECT file_type,
  ROUND(space_used/1024/1024/1024,2) used_gb,
  percent_space_used pct_used
FROM   v$recovery_area_usage;

-- FRA total / remaining
SELECT
  ROUND(space_limit/1024/1024/1024,2) limit_gb,
  ROUND(space_used/1024/1024/1024,2)  used_gb,
  ROUND(space_reclaimable/1024/1024/1024,2) reclaim_gb
FROM   v$recovery_file_dest;

-- Archive log status & location
ARCHIVE LOG LIST;
SELECT sequence#, name, first_time,
       status, archived
FROM   v$archived_log
WHERE  dest_id = 1
ORDER BY sequence# DESC
FETCH FIRST 20 ROWS ONLY;
