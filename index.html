Real-World DBA
Incident Playbook

Step-by-step resolution guides for the most common production database incidents. Learn how senior DBAs respond.

1. Check alert log: tail -200f $ORACLE_BASE/diag/.../alert_*.log

2. Verify listener status: lsnrctl status

3. Attempt startup: connect as SYSDBA → startup

4. Check OS resources — disk space, memory, ulimits

5. Review ORA- errors and escalate if ORA-00600/ORA-07445

1. Check archive log space: SELECT * FROM v$recovery_file_dest;

2. RMAN delete: RMAN> delete archivelog all backed up 2 times to device type disk;

3. Increase FRA size if needed: ALTER SYSTEM SET db_recovery_file_dest_size=200G;

4. Review RMAN retention policy and schedule

1. Identify: SELECT tablespace_name, used_percent FROM dba_tablespace_usage_metrics;

2. Add datafile: ALTER TABLESPACE USERS ADD DATAFILE SIZE 10G AUTOEXTEND ON;

3. Enable autoextend on existing: ALTER DATABASE DATAFILE '...' AUTOEXTEND ON MAXSIZE 30G;

4. Investigate growth — large tables, purge candidates, stale data

1. Find blockers: SELECT blocking_session, sid, sql_id FROM v$session WHERE blocking_session IS NOT NULL;

2. Get SQL: SELECT sql_text FROM v$sql WHERE sql_id = '<id>';

3. Kill if necessary: ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;

4. Escalate to app team to fix missing commits

1. Find top SQL by CPU: SELECT sql_id, elapsed_time, cpu_time FROM v$sql ORDER BY cpu_time DESC FETCH FIRST 10 ROWS ONLY;

2. Check AWR: @$ORACLE_HOME/rdbms/admin/awrrpt.sql

3. Review execution plans for full table scans

4. Gather stale stats: EXEC DBMS_STATS.GATHER_TABLE_STATS('schema','table');

1. Check status: lsnrctl status LISTENER

2. Check listener.log for errors: tail -100 $ORACLE_BASE/diag/tnslsnr/.../listener.log

3. Restart: lsnrctl stop; lsnrctl start

4. Verify tnsnames.ora and sqlnet.ora configuration

5. Check firewall rules if remote connections fail
