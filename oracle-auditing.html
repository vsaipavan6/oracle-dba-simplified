Section 2

Unified Auditing (12c/19c)

Unified Auditing consolidates all Oracle audit trails into a single, tamper-resistant location in the AUDSYS schema.

Key Advantages of Unified Auditing

  • Single view: UNIFIED_AUDIT_TRAIL covers DB actions, RMAN, Datapump, Scheduler, Label Security
  • Write-protected: Audit records in AUDSYS cannot be modified by DBAs (only purge with DBMS_AUDIT_MGMT)
  • Policy-based: Named policies — enable/disable without restarting DB
  • Conditional: Audit only when predicate matches (e.g., only failed logins)
  • Buffered: Records buffered in SGA, written async — minimal performance impact

Enable Unified Auditing (Pure Mode)

-- Check current mode
SELECT value FROM v$option
WHERE  parameter = 'Unified Auditing';
-- TRUE = Pure Unified, FALSE = Mixed mode

-- Enable pure unified auditing (requires relink)
-- 1. Shutdown DB
shutdown immediate;
-- 2. As oracle OS user, relink oracle binary
cd $ORACLE_HOME/rdbms/lib
make -f ins_rdbms.mk uniaud_on ioracle
-- 3. Start DB — unified auditing now active
startup

Creating & Managing Audit Policies

Audit policies are named, reusable rules. Create once, enable for specific users or all users.

Audit Policy — Create, Enable, Query 
-- Policy 1: Audit all failed logins
CREATE AUDIT POLICY failed_logins
  ACTIONS LOGON
  WHEN 'SYS_CONTEXT(''USERENV'', ''AUTHENTICATED_IDENTITY'') IS NOT NULL'
  EVALUATE PER SESSION;
AUDIT POLICY failed_logins WHENEVER NOT SUCCESSFUL;

-- Policy 2: Audit DDL on sensitive schemas
CREATE AUDIT POLICY ddl_changes
  ACTIONS CREATE TABLE, DROP TABLE,
           ALTER TABLE, CREATE INDEX, DROP INDEX
  ACTIONS COMPONENT = DV
  CONTAINER = ALL;
AUDIT POLICY ddl_changes BY APP_USER, DEVELOPER;

-- Policy 3: Audit SYS privilege usage
CREATE AUDIT POLICY sys_privs
  PRIVILEGES DROP ANY TABLE, CREATE ANY TABLE,
              GRANT ANY PRIVILEGE, ALTER SYSTEM;
AUDIT POLICY sys_privs;

-- Disable a policy
NOAUDIT POLICY ddl_changes;

-- View all enabled policies
SELECT policy_name, enabled_option, user_name, success, failure
FROM   audit_unified_enabled_policies;

Fine-Grained Auditing (FGA)

FGA audits access at the row and column level — triggered only when specific data is accessed. Ideal for PCI-DSS card data or HIPAA patient records.

DBMS_FGA — Fine-Grained Audit Policy 
-- Audit SELECT on credit card column when accessed by non-finance users
BEGIN
  DBMS_FGA.ADD_POLICY(
    object_schema   => 'PAYMENTS',
    object_name     => 'CARD_TRANSACTIONS',
    policy_name     => 'CARD_DATA_AUDIT',
    audit_column    => 'CARD_NUMBER,CVV,EXPIRY_DATE',
    audit_condition => 'SYS_CONTEXT(''USERENV'',''SESSION_USER'') NOT IN
                        (SELECT grantee FROM dba_sys_privs WHERE privilege=''FINANCE_READ'')',
    statement_types => 'SELECT,UPDATE',
    enable          => TRUE
  );
END;
/

-- Query FGA audit trail
SELECT timestamp, db_user, object_name,
       policy_name, sql_text
FROM   dba_fga_audit_trail
WHERE  object_name = 'CARD_TRANSACTIONS'
ORDER BY timestamp DESC;

-- Remove FGA policy
EXEC DBMS_FGA.DROP_POLICY('PAYMENTS','CARD_TRANSACTIONS','CARD_DATA_AUDIT');
Section 5

Oracle Database Security Assessment Tool (DBSAT)

DBSAT is a free Oracle tool that scans your database for security misconfigurations, excessive privileges, and compliance gaps.

What DBSAT Checks

  • Basic Security Configuration (listener, audit, password policies)
  • User accounts with default passwords or excessive privileges
  • Audit trail configuration and gaps
  • Network encryption and authentication settings
  • Sensitive data discovery (credit cards, SSNs, email patterns)
  • CIS Benchmark and Oracle security best practices compliance

Running DBSAT

# 1. Download DBSAT from My Oracle Support (Doc 2138204.1)
# 2. Unzip to /opt/dbsat
unzip dbsat.zip -d /opt/dbsat

# 3. Collect (reads DB data)
cd /opt/dbsat
./dbsat collect dbsat_user@ORCL report_ORCL

# 4. Report (generates HTML/JSON/XLSX)
./dbsat report report_ORCL

# 5. Discover (sensitive data patterns)
./dbsat discover -p dbsat_discover.cfg \
  dbsat_user@ORCL discover_ORCL

# Output: report_ORCL.html — open in browser

Audit Trail Maintenance

Audit trails grow rapidly. Regular purging (with archival for compliance) is essential to prevent SYSAUX tablespace overflow.

DBMS_AUDIT_MGMT — Purge & Archive 
-- Check audit trail size
SELECT segment_name,
       ROUND(bytes/1024/1024,1) size_mb
FROM   dba_segments
WHERE  segment_name = 'AUD$UNIFIED';

-- Initialize purge (required first time)
BEGIN
  DBMS_AUDIT_MGMT.INIT_CLEANUP(
    audit_trail_type => DBMS_AUDIT_MGMT.AUDIT_TRAIL_UNIFIED,
    default_cleanup_interval => 24  -- hours
  );
END;
/

-- Set last archive timestamp (keeps records after this date)
BEGIN
  DBMS_AUDIT_MGMT.SET_LAST_ARCHIVE_TIMESTAMP(
    audit_trail_type => DBMS_AUDIT_MGMT.AUDIT_TRAIL_UNIFIED,
    last_archive_time => SYSTIMESTAMP - INTERVAL '90' DAY
  );
END;
/

-- Purge records older than last archive timestamp
BEGIN
  DBMS_AUDIT_MGMT.CLEAN_AUDIT_TRAIL(
    audit_trail_type => DBMS_AUDIT_MGMT.AUDIT_TRAIL_UNIFIED,
    use_last_arch_timestamp => TRUE
  );
END;
/
Section 7

Oracle Auditing — Interview Q&A

Traditional Auditing stores records in SYS.AUD$ (DB) or OS files, has separate trails for different components, and DBAs can delete records directly. Unified Auditing (12c+) consolidates all audit records into AUDSYS.AUD$UNIFIED, covers DB actions plus RMAN/Datapump/Scheduler, uses write-protected storage (requires DBMS_AUDIT_MGMT to purge), and supports policy-based configuration without DB restarts.

FGA (via DBMS_FGA) audits at the row/column level with conditions — unlike standard auditing which fires on every matching statement. Use it when you need: (1) PCI-DSS compliance for credit card column access; (2) HIPAA auditing of patient record access; (3) auditing only when a WHERE clause accesses sensitive rows; (4) capturing the actual SQL text that touched sensitive data. FGA records go into DBA_FGA_AUDIT_TRAIL (or UNIFIED_AUDIT_TRAIL in 12c+).

  • Set up automated purge using DBMS_AUDIT_MGMT.CREATE_PURGE_JOB
  • Archive audit records to external storage before purging (for compliance retention)
  • Set LAST_ARCHIVE_TIMESTAMP so purge only removes records past retention period
  • Monitor AUDSYS segment size: query DBA_SEGMENTS for AUD$UNIFIED
  • Tune audit policies — avoid auditing high-frequency operations unnecessarily (e.g., every SELECT on an OLTP table)

SYSDBA connections bypass normal DB audit trails because they connect before the database is fully open. Set AUDIT_SYS_OPERATIONS=TRUE in init.ora — this writes SYSDBA activity to OS audit files (set by AUDIT_FILE_DEST). In Unified Auditing, OS-level SYSDBA records still go to OS files; use the mandatory audit policy ORA_SECURECONFIG which is enabled by default in 19c to capture SYS activity.
