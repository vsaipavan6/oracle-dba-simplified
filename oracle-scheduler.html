Quick: Simple daily scheduler job 
-- Create a simple daily PL/SQL job
BEGIN
  DBMS_SCHEDULER.CREATE_JOB(
    job_name        => 'DAILY_STATS_GATHER',
    job_type        => 'PLSQL_BLOCK',
    job_action      => 'BEGIN DBMS_STATS.GATHER_DATABASE_STATS(cascade=>TRUE); END;',
    repeat_interval => 'FREQ=DAILY;BYHOUR=2;BYMINUTE=0;BYSECOND=0',
    enabled         => TRUE,
    comments        => 'Gather statistics on all objects daily at 2am'
  );
END;

Section 1

Scheduler Architecture

DBMS_SCHEDULER uses named, reusable components — Programs, Schedules, Jobs, Chains, and Windows — that can be combined flexibly.

Program

Defines WHAT to run — a PL/SQL block, stored procedure, external script, or executable. Reusable across multiple jobs.

Schedule

Defines WHEN to run — using calendar strings (FREQ=WEEKLY;BYDAY=MON,FRI) or event-based triggers. Reusable across jobs.

Job

The execution unit — combines Program + Schedule (or inline definitions). Tracks run history, success/failure, duration.

Chain

Sequences multiple jobs with conditional logic — "run Step 2 only if Step 1 succeeded." ETL workflows, multi-phase maintenance.

Window

A time window with a Resource Manager plan — run maintenance jobs only during low-traffic hours with reduced resource priority.

Window Group

A named collection of Windows — "run during WEEKNIGHT_WINDOW or WEEKEND_WINDOW." Auto-stats uses MAINTENANCE_WINDOW_GROUP.

Section 2

Creating Scheduler Jobs

Jobs can run PL/SQL blocks, stored procedures, OS executables, or external scripts. Enable, disable, or run manually at any time.

Job Types & Management 
-- Type 1: PL/SQL Block Job
BEGIN
  DBMS_SCHEDULER.CREATE_JOB(
    job_name        => 'PURGE_OLD_LOGS',
    job_type        => 'PLSQL_BLOCK',
    job_action      => 'BEGIN DELETE FROM app_logs WHERE log_date < SYSDATE-30; COMMIT; END;',
    repeat_interval => 'FREQ=DAILY;BYHOUR=1;BYMINUTE=30',
    enabled         => TRUE
  );
END;
/

-- Type 2: Stored Procedure Job
BEGIN
  DBMS_SCHEDULER.CREATE_JOB(
    job_name        => 'RUN_ARCHIVE_PROC',
    job_type        => 'STORED_PROCEDURE',
    job_action      => 'PKG_ARCHIVE.DO_ARCHIVE',
    repeat_interval => 'FREQ=WEEKLY;BYDAY=SUN;BYHOUR=3',
    enabled         => TRUE
  );
END;
/

-- Type 3: External Script (OS executable)
BEGIN
  DBMS_SCHEDULER.CREATE_JOB(
    job_name        => 'RMAN_BACKUP_JOB',
    job_type        => 'EXECUTABLE',
    job_action      => '/dba/scripts/rman_backup.sh',
    number_of_arguments => 1,
    repeat_interval => 'FREQ=DAILY;BYHOUR=2',
    enabled         => FALSE  -- enable after setting args
  );
  DBMS_SCHEDULER.SET_JOB_ARGUMENT_VALUE('RMAN_BACKUP_JOB',1,'1');
  DBMS_SCHEDULER.ENABLE('RMAN_BACKUP_JOB');
END;
/

-- Run a job manually (immediate)
EXEC DBMS_SCHEDULER.RUN_JOB('DAILY_STATS_GATHER');

-- Disable / Enable
EXEC DBMS_SCHEDULER.DISABLE('PURGE_OLD_LOGS');
EXEC DBMS_SCHEDULER.ENABLE('PURGE_OLD_LOGS');

-- Drop a job
EXEC DBMS_SCHEDULER.DROP_JOB('PURGE_OLD_LOGS', force => TRUE);
Section 3

Reusable Programs & Named Schedules

Separate WHAT from WHEN using named Programs and Schedules — reuse them across multiple jobs.

Create a Reusable Program

-- Named program (reusable)
BEGIN
  DBMS_SCHEDULER.CREATE_PROGRAM(
    program_name => 'PROG_GATHER_STATS',
    program_type => 'STORED_PROCEDURE',
    program_action => 'PKG_MAINTENANCE.GATHER_STATS',
    number_of_arguments => 1,
    enabled => FALSE
  );
  DBMS_SCHEDULER.DEFINE_PROGRAM_ARGUMENT(
    program_name => 'PROG_GATHER_STATS',
    argument_position => 1,
    argument_name => 'p_schema',
    argument_type => 'VARCHAR2',
    default_value => 'ALL'
  );
  DBMS_SCHEDULER.ENABLE('PROG_GATHER_STATS');
END;
/

Create a Named Schedule

-- Named schedule (reusable calendar)
BEGIN
  DBMS_SCHEDULER.CREATE_SCHEDULE(
    schedule_name   => 'SCHED_WEEKNIGHT_2AM',
    repeat_interval => 'FREQ=DAILY;BYDAY=MON,TUE,WED,THU,FRI;
                        BYHOUR=2;BYMINUTE=0;BYSECOND=0',
    comments => 'Weeknights at 2am'
  );
END;
/

-- Create job using named program + schedule
BEGIN
  DBMS_SCHEDULER.CREATE_JOB(
    job_name      => 'JOB_GATHER_MYSCHEMA',
    program_name  => 'PROG_GATHER_STATS',
    schedule_name => 'SCHED_WEEKNIGHT_2AM',
    enabled       => TRUE
  );
END;
/
Section 4

Job Chains — Multi-Step Workflows

Chains link jobs with conditional rules — Step 2 runs only if Step 1 succeeded. Perfect for ETL pipelines and maintenance sequences.

Create a 3-Step ETL Chain 
BEGIN
  -- 1. Create the chain
  DBMS_SCHEDULER.CREATE_CHAIN(chain_name => 'ETL_CHAIN');

  -- 2. Define chain steps (programs)
  DBMS_SCHEDULER.DEFINE_CHAIN_STEP(
    chain_name   => 'ETL_CHAIN',
    step_name    => 'STEP_EXTRACT',
    program_name => 'PROG_EXTRACT_DATA'
  );
  DBMS_SCHEDULER.DEFINE_CHAIN_STEP(
    chain_name   => 'ETL_CHAIN',
    step_name    => 'STEP_TRANSFORM',
    program_name => 'PROG_TRANSFORM_DATA'
  );
  DBMS_SCHEDULER.DEFINE_CHAIN_STEP(
    chain_name   => 'ETL_CHAIN',
    step_name    => 'STEP_LOAD',
    program_name => 'PROG_LOAD_DATA'
  );

  -- 3. Define rules (conditional flow)
  DBMS_SCHEDULER.DEFINE_CHAIN_RULE(
    chain_name => 'ETL_CHAIN', rule_name => 'RULE1',
    condition  => 'TRUE',                 -- Always start extract
    action     => 'START STEP_EXTRACT'
  );
  DBMS_SCHEDULER.DEFINE_CHAIN_RULE(
    chain_name => 'ETL_CHAIN', rule_name => 'RULE2',
    condition  => 'STEP_EXTRACT COMPLETED SUCCESSFULLY',
    action     => 'START STEP_TRANSFORM'
  );
  DBMS_SCHEDULER.DEFINE_CHAIN_RULE(
    chain_name => 'ETL_CHAIN', rule_name => 'RULE3',
    condition  => 'STEP_TRANSFORM COMPLETED SUCCESSFULLY',
    action     => 'START STEP_LOAD'
  );
  DBMS_SCHEDULER.DEFINE_CHAIN_RULE(
    chain_name => 'ETL_CHAIN', rule_name => 'RULE_END',
    condition  => 'STEP_LOAD COMPLETED',
    action     => 'END'
  );

  -- 4. Enable the chain
  DBMS_SCHEDULER.ENABLE('ETL_CHAIN');

  -- 5. Schedule the chain job
  DBMS_SCHEDULER.CREATE_JOB(
    job_name        => 'ETL_CHAIN_JOB',
    job_type        => 'CHAIN',
    job_action      => 'ETL_CHAIN',
    repeat_interval => 'FREQ=DAILY;BYHOUR=22;BYMINUTE=0',
    enabled         => TRUE
  );
END;

Section 5

Monitoring Scheduler Jobs

Use DBA_SCHEDULER_* views to track running jobs, review history, and diagnose failures.

Scheduler Monitoring Queries 
-- All scheduler jobs and status
SELECT job_name, enabled, state, last_start_date,
       last_run_duration, next_run_date
FROM   dba_scheduler_jobs
ORDER BY next_run_date;

-- Currently running jobs
SELECT job_name, elapsed_time, cpu_used, session_id
FROM   dba_scheduler_running_jobs;

-- Job run history (last 7 days)
SELECT job_name, status, actual_start_date,
       run_duration, error#, additional_info
FROM   dba_scheduler_job_run_details
WHERE  actual_start_date > SYSDATE-7
ORDER BY actual_start_date DESC;

-- Failed jobs with error details
SELECT job_name, status, error#, additional_info
FROM   dba_scheduler_job_run_details
WHERE  status != 'SUCCEEDED'
AND    actual_start_date > SYSDATE-1;

-- Stop a running job
EXEC DBMS_SCHEDULER.STOP_JOB('ETL_CHAIN_JOB', force => TRUE);
Section 6

Oracle Scheduler — Interview Q&A

DBMS_JOB is the legacy job scheduler (pre-10g) — it only supports PL/SQL, has no named programs/schedules, limited monitoring, and runs as the submitting user only. DBMS_SCHEDULER (10g+) is the modern replacement — supports PL/SQL, stored procedures, OS executables, and external scripts; named reusable programs and schedules; job chains with conditional logic; resource windows; email notifications; detailed run history in DBA_SCHEDULER_* views. DBMS_JOB is deprecated since 12c; use DBMS_SCHEDULER exclusively.

Use DBMS_SCHEDULER.RUN_JOB('job_name'). By default this runs synchronously (waits for completion). Pass use_current_session=>FALSE for async execution. The job's next_run_date is not affected by manual runs — it still fires on its regular schedule.

MAINTENANCE_WINDOW_GROUP is a pre-defined Oracle window group that includes WEEKNIGHT_WINDOW (Mon-Fri 10pm-6am) and WEEKEND_WINDOW (Sat-Sun all day). Oracle's built-in automatic maintenance jobs — statistics gathering (AUTO_OPTIMIZER_STATS_COLLECTION), segment advisor (AUTO_SPACE_ADVISOR), and SQL Tuning Advisor — are scheduled to run within these windows. DBAs can adjust window start/end times or resource plans to control when maintenance jobs compete for resources.

  • Query DBA_SCHEDULER_JOB_RUN_DETAILS for error# and additional_info
  • Check DBA_SCHEDULER_JOB_LOG for state transitions
  • For EXECUTABLE jobs, check OS-level logs (stderr captured in additional_info)
  • Run the job manually (DBMS_SCHEDULER.RUN_JOB) and check DBMS output
  • Verify the job owner has necessary privileges (grant them explicitly)
  • Check if scheduler is enabled: SELECT value FROM v$parameter WHERE name='job_queue_processes' (must be > 0)
