Why Linux Matters for DBAs

The DBA's OS Foundation

Oracle Database runs on Linux in over 80% of production environments. Linux proficiency is not optional — it is the bedrock of every DBA's toolkit.

Day-to-Day Operations

Navigate file systems, monitor disk usage, search logs, manage processes, transfer files — all standard DBA activities require confident Linux command use.

Automation & Scripting

Shell scripts and cron jobs automate RMAN backups, space checks, log rotation, stats gathering, and health monitoring — saving hours every week.

Performance Analysis

When AWR says "high I/O wait", you need iostat. When memory is low, you need free and vmstat. OS-level tools complete the picture AWR cannot show.

Correlate OS PID → Oracle Session
-- Find OS PID of high-CPU process from top/ps
-- Then run this in SQL*Plus:

SELECT
  s.sid,
  s.serial#,
  s.username,
  s.osuser,
  s.machine,
  s.program,
  s.sql_id,
  s.status,
  p.spid          AS os_pid
FROM   v$session s
JOIN   v$process p ON s.paddr = p.addr
WHERE  p.spid = '&OS_PID';

-- Get the SQL being run by that session
SELECT sql_text
FROM   v$sqlarea
WHERE  sql_id = '&SQL_ID';

-- Kill session from SQL*Plus if needed
ALTER SYSTEM KILL SESSION '&SID,&SERIAL#'
  IMMEDIATE;

-- Background process to OS PID mapping
SELECT name, description, spid
FROM   v$bgprocess b
JOIN   v$process p ON b.paddr = p.addr
ORDER BY name;

#!/bin/bash
ORACLE_SID=ORCL
ORACLE_HOME=/u01/app/oracle/product/19.0.0/dbhome_1
PATH=$ORACLE_HOME/bin:$PATH
FS_THRESHOLD=80     # alert if filesystem > 80% full
TS_THRESHOLD=85     # alert if tablespace > 85% full
MAIL_TO="dba-team@company.com"
ALERT=""

# --- Part 1: OS-level filesystem check ---
echo "=== Filesystem Usage ==="
while read line; do
  PCT=$(echo $line | awk '{gsub(/%/,"",$5); print $5}')
  MNT=$(echo $line | awk '{print $6}')
  if [ "$PCT" -gt "$FS_THRESHOLD" ] 2>/dev/null; then
    ALERT+="FILESYSTEM ALERT: $MNT is ${PCT}% full\n"
    echo "  *** ALERT: $MNT = ${PCT}% used ***"
  fi
done <<(df -h | tail -n +2)

# --- Part 2: Tablespace check via SQL ---
echo "=== Tablespace Usage ==="
TS_OUTPUT=$(sqlplus -s / as sysdba <<EOF
SET PAGESIZE 0 FEEDBACK OFF HEADING OFF TRIMSPOOL ON
SELECT ts.tablespace_name || '|' ||
       ROUND((ts.used_space * 8192)/1048576/1024,1) || 'GB|' ||
       ROUND(ts.tablespace_size * 8192/1048576/1024,1) || 'GB|' ||
       ROUND(ts.used_percent,1) || '%'
FROM   dba_tablespace_usage_metrics ts
WHERE  ts.used_percent > $TS_THRESHOLD
ORDER  BY ts.used_percent DESC;
EXIT;
EOF
)

if [ -n "$TS_OUTPUT" ]; then
  while IFS='|' read tsname used total pct; do
    ALERT+="TABLESPACE ALERT: $tsname is $pct full ($used / $total)\n"
  done <<< "$TS_OUTPUT"
fi

# Send single email if any alerts
if [ -n "$ALERT" ]; then
  echo -e "Space Alert on $ORACLE_SID:\n\n$ALERT" | \
    mail -s "[ALERT] Space Warning - $ORACLE_SID" "$MAIL_TO"
fi

Common Cron Gotchas for DBAs

No .bash_profile Loaded

Cron runs with a minimal environment. ORACLE_HOME, PATH, ORACLE_SID are not set automatically.

Fix: Source profile in the script or set vars in crontab header

% Character in Cron

The % sign is treated as a newline in crontab. Shell date commands like date +%Y%m%d will break.

Fix: Escape with \% or wrap in a shell script instead of inline command

Redirect Stderr

Without 2>&1, errors go to the oracle user's mail or disappear — you never know the job failed.

Fix: Always append >> logfile.log 2>&1

Script Not Executable

Cron silently fails if the script doesn't have execute permission.

Fix: chmod 755 /scripts/rman_backup.sh

Reading free Output

available

The real "how much can be allocated" number. Linux uses free RAM as disk cache, so "free" is always low — "available" is what matters.

buff/cache

Page cache used for disk reads. Linux reclaims this when applications need memory — it is not "wasted".

Swap used > 0

Oracle should NEVER be swapping. If swap is in use, your SGA or PGA is misconfigured or the server is under-provisioned.

HugePages for Oracle

Configure HugePages equal to your SGA size. This prevents Oracle SGA pages from being swapped and eliminates TLB pressure.

# us = user CPU %  sy = system CPU %
# id = idle %  wa = iowait %

What to Watch in vmstat

r > nCPU

CPU Saturation

Run queue longer than CPU count = processes waiting. High-priority Oracle queries competing for CPU.

si/so > 0

Swapping Occurring

Any swap-in or swap-out is a crisis for Oracle. Immediately check SGA/PGA sizes and consider adding RAM.

wa > 10%

High I/O Wait

CPU is idle waiting for disk. Investigate with iostat — likely slow storage or missing Oracle indexes.

sy > 20%

High System CPU

Kernel spending high time. Could be excessive context switches (cs column) or IPC contention with Oracle.

OOM Killer — The DBA's Worst Nightmare

The Linux Out-of-Memory killer terminates processes when RAM is exhausted. It can kill Oracle background processes (SMON, PMON, DBWn), causing the database to crash. Here's how to detect and prevent it.

# Check if OOM killer struck
grep -i "oom\|out of memory\|killed process" \
  /var/log/messages | tail -20

# dmesg for kernel OOM messages
dmesg | grep -i "oom\|killed"
Protect Oracle from OOM killer
# Protect Oracle processes from OOM killer
# Set oom_score_adj to -1000 for each Oracle PID

for pid in $(pgrep -u oracle); do
  echo -1000 > /proc/$pid/oom_score_adj
done

# Prevent SGA from being swapped out
# (via HugePages — already covered)

# Tune memory overcommit
sysctl -w vm.overcommit_memory=2
sysctl -w vm.overcommit_ratio=80
# Add to /etc/sysctl.conf for persistence

Disk full — diagnosis and recovery
STEP 1: Identify full filesystem
df -h

RMAN> CROSSCHECK ARCHIVELOG ALL;

STEP 5: Increase FRA size (if needed)

STEP 6: Verify space recovered
df -h /u01

STEP 1: Check if Oracle processes exist

STEP 1: Confirm high CPU with top

     WHERE p.spid=14523;
